# Настройка сайта

Документ описывает три вещи: как запустить проект локально, как выложить его на Vercel
и как настроить облако Firebase, чтобы правки из панели владельца видели все посетители.

---

## 1. Локальный запуск

```bash
npm install
npm run dev
```

Сайт откроется на `http://localhost:3000`.

Полезные команды:

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Запуск для разработки |
| `npm run build` | Сборка для публикации (папка `dist`) |
| `npm run preview` | Просмотр собранной версии |
| `npm run lint` | Проверка типов TypeScript |
| `npm run images` | Пересобрать варианты фотографий из `src/assets/images/source/` |

---

## 2. Публикация на Vercel

Проект уже настроен файлом `vercel.json`, ничего дописывать не нужно.

1. Зайдите на [vercel.com](https://vercel.com) и нажмите **Add New → Project**.
2. Выберите репозиторий `alexveisman/eatfood`.
3. Vercel сам определит Vite. Проверьте, что поля заполнены так:
   - **Framework Preset:** Vite
   - **Build Command:** `npm run build`
   - **Output Directory:** `dist`
   - **Install Command:** `npm install`
4. Нажмите **Deploy**.

Переменные окружения задавать не нужно: настройки Firebase лежат в
`firebase-applet-config.json` и являются публичными по своей природе — доступ
ограничивают правила базы, а не секретность этих ключей.

Дальше каждый `git push` в ветку по умолчанию будет публиковать сайт автоматически.

### Что настроено в `vercel.json`

- Файлы из `/assets/*` отдаются с кешем на год. Имена файлов содержат хеш содержимого,
  поэтому после обновления сайта браузер гарантированно скачает новую версию.
- `index.html` не кешируется, чтобы обновления появлялись сразу.
- Любой адрес, кроме `/assets/*`, отдаёт `index.html` — это нужно, чтобы работала
  ссылка `/admin`.

## 3. Firebase: чтобы правки видели все

Без этого шага панель владельца сохраняет изменения **только в браузере**, на котором
вы их сделали. Покупатели и другие ваши устройства будут видеть прежнее меню.
Панель честно предупреждает об этом жёлтой полосой «изменения пока видны только
на этом устройстве».

Проект: `crypto-freedom-qq6d2` (см. `firebase-applet-config.json`).

### 3.1. Заведите себе учётную запись владельца

Это логин, которым вы будете входить в панель на сайте. Заводится один раз.

1. Откройте [Firebase Console](https://console.firebase.google.com/) и выберите проект.
2. Слева в меню — **Authentication**. Если открылась страница-приглашение, нажмите
   **Get started** / **Начать**.
3. Вкладка **Sign-in method** → в списке найдите **Email/Password** → откройте →
   переключатель **Enable** → **Save**.
4. Вкладка **Users** → кнопка **Add user**. Введите свою почту и придумайте пароль
   (запишите его). Нажмите **Add user**.

Готово: этой почтой и паролем вы теперь входите в панель владельца на сайте.

### 3.2. Опубликуйте правила базы

Правила — это то, что запрещает посторонним менять ваше меню.

1. Слева в меню — **Firestore Database** → вкладка **Rules** (Правила).
2. Удалите всё, что там написано, и вставьте содержимое файла `firestore.rules`
   из этого репозитория.
3. Нажмите **Publish** (Опубликовать).

Что меняется: раньше правила разрешали запись кому угодно (`allow write: if true`).
Любой человек, открывший сайт, мог из консоли браузера переписать цены или удалить
меню. Теперь менять меню может только тот, кто вошёл под учётной записью из шага 3.1,
а заказы с телефонами покупателей больше не может прочитать посторонний.

### 3.3. Опубликуйте правила хранилища фотографий

1. Слева в меню — **Storage** → вкладка **Rules**.
2. Вставьте содержимое файла `storage.rules`.
3. Нажмите **Publish**.

Firebase Storage — место, куда попадают загруженные фотографии. Когда оно доступно,
фото хранится отдельным файлом и быстро отдаётся посетителям. Если Storage не
настроен, сайт не ломается: фотография встраивается прямо в карточку блюда,
но грузится медленнее, и панель об этом предупреждает.

### 3.4. Проверьте, что всё сработало

1. Откройте сайт, добавьте в конец адреса `#admin`.
2. Войдите **по почте и паролю** из шага 3.1.
3. Вверху панели должна быть зелёная полоса: «Вы вошли как … — изменения увидят все
   посетители сайта».

Если вместо неё жёлтая полоса «Режим „только это устройство“» — значит вход по почте
не выполнен, и правки останутся в вашем браузере. Выйдите и войдите заново по почте.

### 3.5. Если сейчас нет времени на настройку

Можно ничего не делать: сайт и панель будут работать, но правки останутся только
в вашем браузере, а база — открытой для записи кому угодно. Это временное решение,
не откладывайте настройку надолго.

## 4. Панель владельца

Открывается тремя способами: `ваш-сайт/#admin`, `ваш-сайт/admin` или `ваш-сайт/?admin`.

### Два способа входа

**Почта и пароль** (основной) — учётная запись из шага 3.1. Только этот вход даёт
право менять меню для всех посетителей: база проверяет именно его.

**PIN** (запасной) — открывает панель, но правки сохраняются только в текущем
браузере. Нужен, пока учётной записи нет. Стандартный PIN — **2026**, смените его:
панель → вкладка **Настройки**.

PIN проверяется в браузере, поэтому база о нём ничего не знает — это замок на двери
панели, а не защита данных. Сессия входа истекает через 12 часов.

### Вкладки панели

- **Фотографии** — загрузка снимков пачкой. Блюдо подставляется по имени файла;
  если совпадение неуверенное, поле остаётся пустым и его нужно выбрать вручную.
  Ничего не сохраняется, пока блюдо не выбрано.
- **Блюда** — список с поиском, стрелками для изменения порядка, редактированием
  и удалением. В редакторе доступны все поля карточки, включая вес, условия
  хранения, инструкцию по разогреву и метку «только под заказ».
- **Галерея** — снимки для ленты под меню, не привязанные к блюдам.
- **Настройки** — смена PIN и возврат меню к исходному виду.

## 5. Фотографии блюд

Фотографий в сборке нет — сайт не тащит с собой чужие стоковые снимки. Каждое фото
вы добавляете сами: панель владельца → вкладка **Фотографии**. Можно выбрать сразу
несколько файлов; блюдо подставится по имени файла, а где не подставится — выберете
из списка.

Снимок сжимается прямо в браузере, поэтому фотографии с телефона загружать можно
без подготовки. У блюда, для которого фото ещё не загружено, показывается заглушка.
