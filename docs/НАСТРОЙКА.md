# Настройка сайта

Документ описывает три вещи: как запустить проект локально, как выложить его на Vercel
и как настроить облако Firebase, чтобы правки из панели владельца видели все посетители.

---

## 1. Локальный запуск

```bash
npm install
npm run dev
```

Сайт откроется на `http://localhost:3000`.

Полезные команды:

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Запуск для разработки |
| `npm run build` | Сборка для публикации (папка `dist`) |
| `npm run preview` | Просмотр собранной версии |
| `npm run lint` | Проверка типов TypeScript |
| `npm run images` | Пересобрать варианты фотографий из `src/assets/images/source/` |

---

## 2. Публикация на Vercel

Проект уже настроен файлом `vercel.json`, ничего дописывать не нужно.

1. Зайдите на [vercel.com](https://vercel.com) и нажмите **Add New → Project**.
2. Выберите репозиторий `alexveisman/eatfood`.
3. Vercel сам определит Vite. Проверьте, что поля заполнены так:
   - **Framework Preset:** Vite
   - **Build Command:** `npm run build`
   - **Output Directory:** `dist`
   - **Install Command:** `npm install`
4. Нажмите **Deploy**.

Переменные окружения задавать не нужно: настройки Firebase лежат в
`firebase-applet-config.json` и являются публичными по своей природе — доступ
ограничивают правила базы, а не секретность этих ключей.

Дальше каждый `git push` в ветку по умолчанию будет публиковать сайт автоматически.

### Что настроено в `vercel.json`

- Файлы из `/assets/*` отдаются с кешем на год. Имена файлов содержат хеш содержимого,
  поэтому после обновления сайта браузер гарантированно скачает новую версию.
- `index.html` не кешируется, чтобы обновления появлялись сразу.
- Любой адрес, кроме `/assets/*`, отдаёт `index.html` — это нужно, чтобы работала
  ссылка `/admin`.

## 3. Firebase: чтобы правки видели все

Без этого шага панель владельца сохраняет изменения **только в браузере**, на котором
вы их сделали. Покупатели и другие ваши устройства будут видеть прежнее меню.
Панель честно предупреждает об этом жёлтой полосой «изменения пока видны только
на этом устройстве».

Проект: `crypto-freedom-qq6d2` (см. `firebase-applet-config.json`).

### 3.1. Создайте пользователя-владельца

1. [Firebase Console](https://console.firebase.google.com/) → ваш проект.
2. **Authentication → Sign-in method** → включите **Email/Password**.
3. **Authentication → Users → Add user** — укажите свою почту и пароль.

### 3.2. Опубликуйте правила базы

1. **Firestore Database → Rules**.
2. Вставьте содержимое файла `firestore.rules` из репозитория.
3. Нажмите **Publish**.

Что меняется: раньше правила разрешали запись кому угодно
(`allow write: if true`). Любой человек, открывший сайт, мог из консоли браузера
переписать цены или удалить всё меню. Теперь запись разрешена только вошедшему
пользователю, а заказы покупателей больше не может прочитать посторонний.

### 3.3. Опубликуйте правила хранилища

1. **Storage → Rules**.
2. Вставьте содержимое файла `storage.rules`.
3. Нажмите **Publish**.

Firebase Storage — это место, куда попадают загруженные фотографии. Когда оно
доступно, фото хранится отдельным файлом и отдаётся через CDN. Если Storage
недоступен, сайт не ломается: фотография встраивается прямо в карточку блюда,
но грузится медленнее, и панель об этом предупреждает.

### 3.4. Если нужно опубликовать сайт до настройки входа

Временно замените в `firestore.rules` и `storage.rules` вызовы `isOwner()` на `true`
в блоках `write`. Сайт заработает сразу, но база останется открытой для записи
кому угодно — вернитесь к этому шагу как можно скорее.

## 4. Панель владельца

Открывается тремя способами: `ваш-сайт/#admin`, `ваш-сайт/admin` или `ваш-сайт/?admin`.

Стандартный PIN — **2026**. Смените его сразу: панель → вкладка **Настройки**.

### Что важно понимать про PIN

PIN проверяется в браузере, поэтому он закрывает только вход в панель — это замок на
двери, а не защита самих данных. Реально запретить посторонним менять меню могут
только правила Firestore из шага 3. Сессия входа истекает через 12 часов.

### Вкладки панели

- **Фотографии** — загрузка снимков пачкой. Блюдо подставляется по имени файла;
  если совпадение неуверенное, поле остаётся пустым и его нужно выбрать вручную.
  Ничего не сохраняется, пока блюдо не выбрано.
- **Блюда** — список с поиском, стрелками для изменения порядка, редактированием
  и удалением. В редакторе доступны все поля карточки, включая вес, условия
  хранения, инструкцию по разогреву и метку «только под заказ».
- **Галерея** — снимки для ленты под меню, не привязанные к блюдам.
- **Настройки** — смена PIN и возврат меню к исходному виду.

## 5. Замена встроенных фотографий

Встроенные фото лежат в `src/assets/images/source/`. Чтобы заменить их:

1. Положите новый файл в `src/assets/images/source/` (можно любого размера).
2. Выполните `npm run images` — скрипт создаст варианты 400/800/1200px в формате
   WebP, запасной JPEG и обновит `src/assets/images/manifest.ts`.
3. Если имя файла изменилось, поправьте ссылку в `src/data/menuData.ts`.

Скрипт запускается автоматически перед каждой сборкой (`npm run prebuild`).

Через панель владельца фотографии меняются без пересборки — этот раздел нужен
только для фото, заложенных в код.
